# Единая архитектура прохождения: «страховка вместо удачи»

Цель: бот сам проходит Minecraft до титров (Normal, мобы, keepInventory=false, без выдач/ТП/эффектов).
Документ: (1) что ломалось — по данным, (2) что сломается дальше, (3) общий корень, (4) единое решение.

## 1. Что было — данные марафонов

Источник: логи двух марафонных сессий (18-дневная + текущая), ~300 смертей.

| Фаза в момент смерти | Смертей (старый марафон, 226) | Текущий чистый мир (77) |
|---|---|---|
| wood | 121 (54%) | ~25 |
| stone | 46 | ~6 |
| iron | 43 | ~20 |
| diamond/portal | 1 | ~25 (одна точка ≈ -180,y16-28,905 — ~15 раз) |
| nether | 0 (чисто) | 4 (до сброса мира, с ассистами) |

Убийцы (старый марафон): скелет 35, зомби 33, креепер 30, утопленник 29, паук 27, неизвестно 34, разбойник 12, всадник-скелет 7, лава 2+.
Вехи чистых прогонов: дальше `DIAMOND_STRIP / OBSIDIAN / PORTAL` не доходило ни разу; Незер, блейзы, жемчуг, крепость, Энд — **0 проверок в реальном прохождении**.

Классы прошлых проблем:
1. **Смертельный тредмил**: смерть → голый респавн в том же опасном месте → смерть. Респавн на мировом спавне в бассейне с утопленниками/зомби; дом-якорь внутри той же зоны.
2. **Регресс прогресса**: `detectPhase()` считается только по инвентарю → любая смерть = фаза wood, даже если в сундуке лежат кирка, железо и алмазы.
3. **Повтор одной и той же ошибки**: портал-фаза умерла ~15 раз в одной точке (лава/скелеты y≈16-28) — нет памяти «этот способ/место не работает».
4. **Риск не моделируется**: бот делает поверхностную работу ночью без брони, лезет в пещеры со скелетами голым, плывёт через воду с утопленниками. Каждая ситуация закрыта отдельной заплаткой (clear.js — 2600 строк частных случаев: grave-first, seal-now, pack-burrow, flee-legs, anchor-march...).
5. **Ловушки и зависания**: запечатанная пещера, голодная ловушка, `/kill` без прав, `cannot harvest stone with hand`, await-дедлоки (watchdog).
6. **Броня почти не делается**: железо уходит в инструменты; броня крафтится только «если останется».

## 2. Что будет дальше (ещё не встречалось, но гарантированно встретится)

Поздние фазы сейчас — заглушки (`phaseNetherBlaze/Pearls/Stronghold/Dragon` = случайная ходьба + attack):
- **Незер**: нет поиска крепости (кроме `findBlock nether_bricks` в 64м), нет моста через лаву, гасты сбивают в лаву, пиглины без золотой брони агрессивны, нет защиты обратного портала, нет записи координат портала-возврата, нет огнестойкости.
- **Блейзы**: нужно 6-7 стержней; бой в открытую = смерть от огня. Нужна позиция за укрытием у спавнера + щит.
- **Жемчуг**: случайная ходьба за эндерменами; нет бартера, нет охоты ночью в пустыне/равнине, нет защиты от агра (взгляд).
- **Крепость/стронгхолд**: глаз бросается, но нет триангуляции, нет копания к (8,8) чанка, нет учёта 20% поломки глаза (нужно 12-14 глаз), нет поиска рамки по комнатам.
- **Энд**: падение в пустоту, эндермены, нет столба/лестницы к кристаллам в клетках, нет стратегии кроватей у фонтана, нет запаса блоков, смерть в Энде = потеря всего (вещи падают в пустоту).
- **Общее**: смерть в Незере/Энде без резервного комплекта = откат на часы.

## 3. Корень: одна архитектурная ошибка

Все пункты выше — следствия одного: **прогресс и выживание держатся на одной жизни и на одном инвентаре**, а решения «что делать сейчас» не учитывают, сколько стоит ошибка.
Удача здесь — это то, что *в этой конкретной жизни* не встретился скелет. Систематизировать удачу = сделать так, чтобы любая смерть стоила дёшево и чтобы опасные действия делались только тогда, когда к ним готов.

## 4. Единое решение: Страховочная архитектура (4 опоры)

```
             ┌──────────── Risk Governor ────────────┐
 Perception →│ danger(t) = ночь, свет, мобы, HP, еда, │→ разрешённый класс работ
             │ теплокарта смертей, броня, фаза        │   (SAFE / LOW / MID / HIGH)
             └─────────────────┬──────────────────────┘
                               ▼
 Capital Ledger ──► Phase = f(инвентарь ∪ склад ∪ база)  (смерть не откатывает фазу)
                               ▼
 Strategy Ledger ─► для цели выбирается способ (несколько на цель),
                    провал → бюджет попыток → смена способа/места
                               ▼
 Insurance ───────► перед HIGH-риском: кровать-респавн в безопасной базе +
                    резервный комплект в сундуке базы (страховой полис)
```

### 4.1 Capital Ledger (капитал вместо инвентаря)
- Каждый сундук-склад помнит своё содержимое (обновляется при deposit/withdraw), файл `logs/ledger.json`.
- `capitalPhase()` = фаза по сумме (инвентарь + доступные склады). После смерти бот знает: «у меня есть железная кирка и 3 алмаза в базе» → фаза остаётся diamond, первая задача — `stashRecover`, а не рубить дерево.

### 4.2 Insurance (страховой полис)
- **База** = закрытая освещённая комната под землёй (не в зоне смертей), кровать + сундук + верстак + печь.
- **Кровать-якорь только в базе**. Респавн → сразу внутри стен, с сундуком рядом.
- **Полис**: перед выходом на работу риска MID/HIGH в сундуке базы должен лежать резервный комплект текущего уровня (кирка, меч, еда ×8, блоки, + для Незера: щит, броня). Нет полиса → сначала делаем полис (дублируем инструменты), потом идём.
- Смерть стоит: время ходьбы от базы, а не откат по фазам.

### 4.3 Risk Governor (контроль риска)
- Единая функция `assessRisk()` → уровень опасности 0..1 + причины. Входы: время суток, свет, число/тип враждебных мобов в 24м, HP, голод, уровень брони/оружия, вода под ногами, теплокарта смертей.
- У каждой работы есть класс риска; работа разрешена, если `danger ≤ допуск(класс, снаряжение)`. Иначе — безопасная работа: шахта из базы, крафт/плавка, ферма, сон.
- Ночью без брони поверхность запрещена всегда (это убирает главный класс смертей wood/stone).

### 4.4 Strategy Ledger (стратегии с запасными путями)
- Цель → несколько способов. Пример — портал: [ведро+лава (литой портал), руины портала, алмазная кирка+обсидиан]; жемчуг: [эндермены ночью, бартер]; стронгхолд: [триангуляция 2 бросков].
- Журнал попыток `(цель, способ, место)` → успех/смерть/таймаут. После N провалов место помечается, способ получает штраф, выбирается следующий. Конец «15 смертей в одной точке».

### 4.5 Readiness Gates (чек-листы переходов)
- В Незер: железная броня ≥ 3 части, щит, меч, кирка, еда ≥ 16, блоки ≥ 64, золотой шлем/ботинки, огниво, полис в базе, записан портал.
- В Энд: 12+ глаз (запас 2), лук+64 стрелы или кровати ×6, блоки ≥ 128, вода, еда, броня, полис.

## 5. План внедрения (по приоритету данных)
1. Capital Ledger + фаза по капиталу (бьёт по 100% смертей ранних фаз — убирает регресс).
2. Risk Governor + гейтинг работ (ночь/свет/мобы) — снижение частоты смертей.
3. Insurance: база-якорь вне зоны смертей + полис-комплект.
4. Strategy Ledger + перевод портала на литой (bucket) портал с запасными путями.
5. Readiness Gates.
6. Реальные навыки поздней игры: крепость, блейзы, жемчуг, триангуляция, Энд.
7. Метрики в логе: смертей/час по фазам, «цена смерти» (минут до восстановления фазы), MTBF.
