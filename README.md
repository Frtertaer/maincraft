# Opus 5 × Minecraft

Локальный эксперимент: Paper-сервер работает на этом ПК, а `OpusBot` входит в мир отдельным персонажем через Mineflayer. Модель получает структурированное состояние мира, выбирает действие и может автономно добывать ресурсы, крафтить, исследовать и выполнять команды.

## Текущее состояние

Уже проверено реальным запуском:

- Paper 1.21.1 запускается на локальной OpenJDK 21;
- `OpusBot` подключается отдельным offline-персонажем;
- API принимает ключ из `C:\Users\user\Desktop\opus4.8api.txt` и возвращает модель с ID `claude-opus-5`;
- бот осматривает мир, планирует действия, добывает древесину и крафтит предметы;
- в контрольном survival-прогоне бот действительно изготовил `spruce_planks` и `crafting_table`; результат подтверждён сервером по настоящему инвентарю;
- POV бота открывается на `http://127.0.0.1:3007`; viewer слушает только localhost;
- сервер и бот корректно останавливаются без ошибок.

## Может ли Opus пройти Minecraft

Технически такой агент может пройти игру, но текущая версия пока не гарантирует полное автономное прохождение.

Сейчас реализованы:

- перемещение, поиск и добыча блоков;
- крафт и выбор подходящего инструмента;
- плавка в печи;
- еда, сон и ограниченный ближний бой;
- установка и активация блоков/предметов;
- просмотр, изъятие и складывание предметов в контейнеры;
- многошаговая цель, история действий и лимиты API;
- координаты мобов, предметов, ресурсов и опасностей.

Для надёжного полного прохождения ещё нужны высокоуровневые детерминированные навыки: стабильное строительство Nether-портала, навигация по Nether/stronghold, добыча blaze rods и pearls, дальний бой с драконом, восстановление после смерти и проверяемый детектор победы. Opus уже может развиваться и экспериментировать в survival, но фразу «игра пройдена» следует считать доказанной только после реального убийства дракона и серверного подтверждения.

## Лицензия Minecraft

Для режима `Paper + OpusBot + browser viewer` купленная копия Minecraft не нужна: игровой клиент вообще не запускается.

Собственная лицензия Minecraft Java нужна только если вы хотите лично войти в этот мир официальным клиентом. Боту отдельная лицензия не нужна. Сервер используется только локально с `online-mode=false` и привязкой к `127.0.0.1`.

Первоначальная установка уже выполнена. Для воспроизводимого развёртывания с нуля:


Обычный запуск выполняется в двух окнах PowerShell.

Окно 1 — сервер:

```powershell
cd D:\maincraft\server

```

Окно 2 — бот:


## Управление ботом

Команды вводятся в локальной консоли бота:

```text
status
!mode auto
!mode hybrid
!mode listen
!mode observe
!goal добудь дерево, сделай каменные инструменты и безопасное убежище
!pause
!resume
!stop
!vision on
!vision off
exit
```

Режимы:

| Режим | Поведение |
|---|---|
| `auto` | Самостоятельно развивается по текущей цели |
| `hybrid` | Развивается сам и принимает локальные команды |
| `listen` | Действует только после команды |
| `observe` | Почти не меняет мир |

Команды из игрового чата по умолчанию отключены: offline-ник нельзя считать надёжной авторизацией. Это также защищает API-бюджет от посторонних команд.

## API и ключ

Ключ читается в таком порядке:

1. переменная окружения `OPUS_API_KEY`;
2. файл `C:\Users\user\Desktop\opus4.8api.txt`.

Сырой ключ не записывается в логи и не хранится внутри JSON-конфига. Проверка API:

```powershell
cd D:\maincraft\agent
npm run check-api
```

Важно: проект сейчас обращается к стороннему Anthropic-совместимому endpoint `api.cheat-ai.shop`. Код проверяет HTTPS, разрешённый host, доступность заявленной модели и совпадение ID ответа с `claude-opus-5`, но технически не может криптографически доказать, какая модель находится за сторонним прокси. Используйте только ключ, предназначенный именно для этого сервиса.

В `agent\config.json` установлены ограничения на запросы, частоту и суммарные токены одной сессии.

## Двухмодульный режим (Opus + быстрый контроллер)

По умолчанию Opus 5 вызывается на **каждом** тике (`agent.tickMs`), поэтому реакция на мир ограничена латентностью LLM. В `agent\config.controller.json` включён стек «два разума»:

- **Планировщик (медленный разум).** Opus 5 вызывается раз в `controller.plannerEveryTicks` тиков в фоне и сразу при приказе игрока. Возвращает те же `say/goal/plan/action` плюс `targets` (minecraft id целей на ~30 сек) и `waypoint`.
- **Контроллер (быстрый разум).** На каждом тике выбирает **один глагол из ограниченного набора** (`wait/eat/sleep/flee/attack/equip/pickup/collect/dig/goto_target/goto_waypoint/craft/place/smelt/follow/come/container_*`). Координаты и аргументы вычисляет код из состояния мира — модель не может выдумать позицию или произвольную команду.
- **Гейты.** Решение контроллера пропускается только если `safe` (noul ≥ 0.5) и `confidence ≥ controller.minConfidence`; иначе — `flee`/`wait`. При ошибке контроллера срабатывает `fallbackToLocal` — детерминированные эвристики без сети.
- **Рефлексы.** Локальный combat-reflex (~40 мс) продолжает работать независимо и обрабатывает немедленные угрозы без любой модели.

Запуск:

```powershell
cd D:\maincraft
.\start-bot-controller.ps1 -Controller jev    # TypeSafe System One (API)
.\start-bot-controller.ps1 -Controller laya   # локальная модель (сайдкар)
.\start-bot-controller.ps1 -Controller local  # только эвристики, без модели
```

Либо вручную: `node agent/src/index.js --config agent/config.controller.json`.

### Jev (api.typesafe.ai)

Ключ кладётся в `agent\.env` (файл уже в `.gitignore`) или в переменную окружения `TYPESAFE_API_KEY` — см. `agent\.env.example`. На каждый тик уходит один POST `/v1/systemone` с тремя типизированными вопросами (choice/noul/score); типичный ответ — ~150 мс.

### Laya (convaiinnovations/laya, локально)

Полностью локальный контроллер на открытой модели решений (~421M параметров, Apache-2.0). Сайдкар на Python-stdlib:

```powershell
pip install laya
python agent\tools\laya_server.py   # LAYA_PORT=8091 LAYA_DEVICE=cpu
```

Затем `-Controller laya`. На CPU решение занимает ~0,4-0,9 c на все три вопроса; на GPU — десятки миллисекунд. URL сайдкара принимается только loopback (`controller.laya.url`).

### Совместимость

Без блока `controller` в конфиге бот работает ровно как раньше — Opus каждый тик. При `controller.type` = `off`/`jev`/`laya`/`local` поведение меняется только между вызовами планировщика; приказы игрока по-прежнему получают полную мощь Opus (свободный `action`).

## «Нейроскайрим»-режим (разговорный спутник)

В `agent\config.companion.json` включён режим живого NPC-компаньона (по мотивам SkyrimNet/Mantella):

- **Свободный диалог.** Любая строка в игровом чате от разрешённых ников (`agent.chatUsers`) идёт не в планировщик, а в диалоговый пайплайн: один вызов LLM возвращает `{say, action, task, mood}`. `say` — реплика в чат; `action` — жест/действие тела (`wave`, `sit`, `follow`, `give:предмет`, `attack`, `look`…); `task` — реальная работа («добудь дерево» → приказ мозгу); `mood` — настроение.
- **Персонаж и память.** `agent.persona` задаёт характер; модуль `mantella` хранит историю чата в `logs/mantella-memory/<world>/<bot>/chat.jsonl` и периодически конденсирует её в summary, который подаётся в контекст диалога.
- **Автономность.** Бот слушает события мира (смерть, зашёл/вышел игрок, начался дождь, майлстоуны прохождения) и редко — не чаще `mantella.ambientEveryMs` — комментирует их репликой от своего имени.
- **Голос (опционально).** `mantella.tts`: `none` | `sapi` | `edge` | `silero` | `voice` (внешний сервер `mantella.voiceUrl`); `mantella.stt: whisper` — распознавание голоса через voice-сервер.

Запуск:

```powershell
cd D:\maincraft
.\start-bot-companion.ps1 -PlayerName Steve -Controller local   # или jev / laya / off
```

### Другой ИИ вместо Opus

Диалог и планировщик работают на любом OpenAI-совместимом API (OpenRouter, VseGPT, NanoGPT, локальный vLLM/Ollama). В конфиге:

```json
"api": {
  "protocol": "openai",
  "baseUrl": "https://openrouter.ai/api/v1",
  "allowedHosts": ["openrouter.ai"],
  "allowCustomHost": true,
  "keyEnv": "OPENAI_API_KEY",
  "model": "qwen/qwen-2.5-72b-instruct",
  "requireExactModel": false
}
```

`protocol: "anthropic"` (по умолчанию) — `/v1/messages` + `x-api-key`; `protocol: "openai"` — `POST /chat/completions` + `Bearer`-ключ, preflight через `GET /models` (мягкий: если у прокси нет `/models`, бот стартует с предупреждением). Ключ — только через env/.env, не в конфиге.

### Пройти игру до дракона (+ визер и варден)

`!clear` (или попросить в чате: «пройди игру») запускает `ClearRunner` — детерминированный движок фаз (дерево → камень → железо → броня/еда → алмазы → портал → незер → стержни → жемчуг → очи → стронгхолд → энд → дракон). После смерти дракона бот идёт к выходному порталу фонтана, прыгает в него и проходит титры — цель считается выполненной только когда он воскрес в обычном мире (смерть в энде не засчитывается: бот вернётся за титрами). Майлстоуны бот озвучивает в чат; статус — `!clear status`, остановка — `!clear stop`. Отдельный самостоятельный скрипт `agent\src\clear-run.js` продолжает работать как раньше.

Эпилог-боссы (опционально, после дракона или отдельно):

- `!clear all` / `!clear боссы` — дракон → визер → варден подряд.
- `!clear визер` — охота на визер-скелетов в крепости (3 черепа) → soul sand ×4 → возврат в обычный мир → постройка Т-образного призыва → бой (`witherTick` из boss-combat).
- `!clear варден` — поиск sculk-блоков в deep dark (спуск ниже y≈0) → провокация шрикера шумом до спавна → бой (`wardenTick`: duck/kite/hit).

В чате то же самое: «убей визера», «сразись с варденом» — диалоговый `task` маршрутизируется в соответствующую цель. Честные ограничения: черепа падают ~2,5% — сбор занимает десятки минут; варден очень опасен (500 hp, sonic boom) — бой best-effort, бот может погибнуть и вернуться.

## Vision (Opus 5)

Есть два режима:

| source | Что видит модель |
|---|---|
| `viewer` (рекомендуется) | Синтетический first-person JPEG из `bot.world` (raycast + canvas). Без desktop capture. |
| `file` | Читает готовый JPEG `D:\maincraft\logs\vision_frame.jpg` (ручной/внешний захват). |

Запуск vision-версии (отдельный конфиг):

```powershell
cd D:\maincraft\server
.\start-server.ps1

# другое окно
cd D:\maincraft
.\start-bot-vision.ps1
```

Конфиг: `agent\config.vision.json` — `vision.enabled=true`, `source=viewer`, кадр раз в `everyNTicks` brain-тиков (`tickMs` по умолчанию 5000 ms). Последний кадр пишется в `logs\vision_frame.jpg` для отладки.

В уже запущенном боте (если source=file|viewer):

```text
!vision on
!vision off
```

Только из **локальной** консоли бота. Desktop/screen capture намеренно запрещён (безопасность).

**Стоимость:** каждый vision-тик шлёт JPEG в `claude-opus-5` — токенов заметно больше, чем у text-only. Для экономии подними `everyNTicks` или `tickMs`.

Browser viewer (`http://127.0.0.1:3007`) **не** отправляет изображение модели и работает отдельно от vision.

## Безопасность

- Paper слушает только `127.0.0.1:25565`.
- Viewer слушает только `127.0.0.1:3007`.
- Не меняйте `server-ip` и не публикуйте offline-сервер в интернет.
- Перед важным экспериментом копируйте `server\world`.
- API-вызовы расходуют токены; для длительных сессий используйте `listen` или увеличьте `tickMs`.
- В npm-аудите нет high/critical проблем; остаётся транзитивное moderate-предупреждение `uuid`, для которого у текущей цепочки Mineflayer нет готового исправления.
